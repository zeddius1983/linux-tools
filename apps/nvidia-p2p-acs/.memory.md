## nvidia-p2p-acs

Host-only app (no container). Installs a boot-time systemd oneshot that clears PCIe
ACS "P2P Request/Completion Redirect" on every bridge above the target GPUs, so a
PCIe switch routes GPU↔GPU peer traffic directly. Consolidates one of the five loose
`~/` NVIDIA host artifacts. See [[nvidia-p2p-patch-kernel-update-orphaning]].

## Implementation

- **Container-less host-only pattern** (`host-only` + `install.sh`, no Dockerfile) —
  same as `nvidia-cdi-regenerate`; `is_hostonly_installer` in `lib/helpers.sh`.
- **`install.sh`**: auto-installs `pciutils` if `setpci` is missing (apt/dnf/pacman/
  zypper detect), installs the script → `/usr/local/sbin/nvidia-p2p-acs.sh` (0755) and
  the unit → `/etc/systemd/system`, `enable --now`. `uninstall` removes both.
- **`nvidia-p2p-acs.sh`**: finds GPUs by PCI ID (`P2P_GPU_PCI_IDS`, default
  `10de:2204` = RTX 3090; the unit passes it via `Environment=`), `realpath`s each
  GPU's sysfs node, walks the ancestry with `dirname`, and for every parent bridge
  that has an ACS cap does `setpci -s <bdf> ECAP_ACS+0x6.w=0000`. Resolving bridges
  live makes it **renumber-proof** — no hardcoded BDFs.
- **Cross-distro:** only needs pciutils (same package name on all families) + systemd.

## Pitfalls and notes

- **The reboot regression this fixes:** with `intel_iommu=on`, the kernel re-runs
  `pci_enable_acs()` each boot and re-enables ACS redirect on the switch's downstream
  ports. Symptom: `nvbandwidth` aborts with `Invalid value when checking the pattern`
  (data corruption) and P2P collapses to ~1 GB/s, even though the patched module is
  loaded and connectivity shows enabled. Confirmed on this host 2026-07-24.
- **Why walk the topology instead of hardcoding BDFs:** the two 3090s route through
  bridges `02:00.0`, `02:08.0`, `04:10.0`, `0b:10.0` on this rig. The deeper ones
  (`04:10.0`/`0b:10.0`) can renumber if cards under the switch change. A
  `pci=disable_acs_redir=<bdf-list>` cmdline works but silently no-ops on stale BDFs;
  the live walk doesn't.
- **`setpci` ECAP_ACS control register** is at offset `+0x6.w`. `001d` =
  SrcValid+ReqRedir+CmpltRedir+UpstreamFwd; zeroing it clears the two redirect bits
  that break P2P. Reading `ECAP_ACS+0x6.w` on a bridge without an ACS cap errors
  (`Extended capability 000d not found`) — the script swallows that and skips.
- **Clique poisoning:** only list P2P-capable GPUs in `P2P_GPU_PCI_IDS`. A non-P2P
  card in the set (RTX 3080 `10de:2206` on the root complex here) drags the good pair
  down to ~1 GB/s. `nvbandwidth --pair`/`CUDA_VISIBLE_DEVICES` do the same at test time.
- **Requires `iommu=pt`** for full bandwidth; that's a kernel cmdline concern outside
  this app's scope (documented in the README).
- **ACS was long misdiagnosed as a "red herring"** — the earlier dump checked the
  wrong bridge ports. Corrected in `apps/nvbandwidth/.memory.md`.
- Reading ACS control bits / writing them needs **root** — hence the boot service; a
  user can't do it from inside a rootless container.
