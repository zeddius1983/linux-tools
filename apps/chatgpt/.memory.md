## chatgpt

OpenAI's ChatGPT desktop app for Linux (preview, https://learn.chatgpt.com/docs/linux/linux-app),
from OpenAI's official `.deb` in an `ubuntu:24.04` box, exported to the host
menu plus a `chatgpt` launcher on the host `PATH`. It is an Electron app built on
the Codex desktop app: it bundles its own `codex` app-server
(`/usr/lib/chatgpt/resources/codex`) and runs it locally over stdio.

## Implementation

- `Dockerfile` — `FROM docker.io/ubuntu:24.04` (Ubuntu 24.04 is a supported
  target upstream). Downloads
  `https://persistent.oaistatic.com/codex-app-prod/linux/deb/latest/chatgpt_${arch}.deb`
  with `arch=$(dpkg --print-architecture)` (amd64 and arm64 are both published)
  and installs it with `apt-get install ./file` so apt resolves its long
  `Depends:` list. Extras: `curl` (download + host-spawn bootstrap), `git`
  (package Recommends, and shared-`$HOME` dotfiles), `libsecret-1-0` (Electron
  safeStorage → host keyring), `libpulse0` (audio), Noto fonts (emoji/CJK).
- The package's `postinst` writes OpenAI's signing key to
  `/usr/share/keyrings/chatgpt-archive-keyring.gpg` and a deb822 source at
  `/etc/apt/sources.list.d/chatgpt.sources`
  (`https://persistent.oaistatic.com/codex-app-prod/linux/deb`, suite `stable`),
  so `apt upgrade` inside the box updates the app between image rebuilds.
- `exports` — `app:chatgpt:ChatGPT` (the package ships
  `/usr/share/applications/chatgpt.desktop`, so `distrobox-export --app` works
  and keeps its `MimeType=`/`codex://` handler) and `bin:chatgpt` (for launching
  with flags such as `--ozone-platform=wayland`).
- `/usr/bin/chatgpt` is a symlink to `/usr/lib/chatgpt/codex-launcher`, a
  two-line shell script that execs `/usr/lib/chatgpt/ChatGPT`. `command -pv`
  resolves it as `/bin/chatgpt` (usrmerge), which is fine.
- `icon.png` — the package's 1024px `/usr/share/pixmaps/chatgpt.png` resized to
  256px.
- `category` = `AI / LLM`.

## Pitfalls and notes

- **Profile dir is `~/.config/Codex`, not `~/.config/ChatGPT`.** Visible in the
  window's WM_CLASS: `"chatgpt (/home/<user>/.config/Codex)", "Chatgpt"`. Codex
  state lives in `~/.codex`, shared with the `codex-cli` app.
- **Startup log is full of `Failed to connect to socket /run/dbus/system_bus_socket`.**
  Harmless: Distrobox boxes have no system D-Bus (same as `chrome-box`); the
  session bus works. Only UPower battery queries fail.
- **GPU**: no `create_flags` needed. Verified on X11 (Mint 22.3, Radeon 8060S):
  the GPU process starts with `--ozone-platform=x11` and no `--disable-gpu` or
  SwiftShader flags. Same reasoning as `apps/chrome/.memory.md` (distrobox-init
  installs Mesa, `/dev/dri` is shared).
- **The `.deb` ships an AppArmor profile** (`/etc/apparmor.d/chatgpt`,
  `flags=(unconfined)` + `userns`) that postinst tries to load. Inside the box
  `apparmor_parser` isn't installed, so it's skipped. The Chromium sandbox still
  works under rootless Podman, just as it does for Chrome.
- **The `.deb` is ~500 MB**, so the image is large and a rebuild re-downloads it.
  Prefer `apt upgrade` in the box for routine updates.
- The `.desktop` advertises `x-scheme-handler/http`/`https`, so ChatGPT can appear
  in host "Open with" / default-browser lists. That's upstream's choice, and it's
  harmless unless the user selects it.
- Commands the app/Codex runs in local projects execute inside the box, not on
  the host — host-only toolchains aren't visible.
- Computer Use is not available in the Linux preview (upstream).
