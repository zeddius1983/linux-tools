## amdgpu_top

AMD GPU/APU monitor (TUI + GUI) by Umio-Yasuno, from its latest GitHub release
RPM in a `fedora:43` box. Exported as a host CLI (`amdgpu_top`), a terminal menu
entry, and a GUI menu entry.

## Implementation

- **Base image**: `registry.fedoraproject.org/fedora:43`, per the repo's
  "AMD GPU / egui GUI" row: Mesa Vulkan/GL/EGL, `libdrm`, glvnd, and the X11 +
  `libxkbcommon(-x11)` set the egui/WGPU GUI needs.
- **Install**: the GitHub API's `releases/latest` → the `x86_64.rpm` asset URL →
  `dnf install <url>`. No version pin; each build takes the newest release.
- **Wrappers** in `/usr/bin` (`command -pv` needs them there): the real binary is
  moved to `amdgpu_top-bin`; `amdgpu_top` = `--dark "$@"`, `amdgpu_top-gui` =
  `--gui "$@"`.
- **Exports**: `bin:amdgpu_top`, `desktop:amdgpu_top:amdgpu_top`,
  `gui:amdgpu_top-gui:amdgpu_top GUI`.
- No `create_flags`: Distrobox shares `/dev/dri`.
- **README.md** added in Oct 2026 (it was missing, so the dashboard info panel was
  empty).

## Pitfalls and notes

- Verified 2026-10-11: v0.11.5 (= latest release), detects "Radeon 8060S
  Graphics", and `-J -n 1` JSON works through the exported host command.
- The release-URL lookup is an unauthenticated GitHub API call during the build,
  so it is subject to the 60/hour anonymous rate limit.
- `x86_64` RPM only, so the image is effectively amd64-only, though the
  Dockerfile doesn't pin `--platform`.
- `git` isn't installed, though the repo convention is to include it so the
  shared-`$HOME` dotfiles work in every box.
- The first invocation after the box has stopped prints Distrobox's "Container
  Setup Complete!" banner before amdgpu_top's own output.
