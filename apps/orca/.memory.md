## orca

Orca (https://github.com/stablyai/orca, MIT): Stably AI's Electron desktop IDE for
running many coding agents (Claude Code, Codex, OpenCode, Copilot, ...) in
parallel, each in its own git worktree. Packaged from the official `.deb` of a
release picked in the wizard, in an `ubuntu:24.04` box, and exported to the host
menu. Added Oct 2026 at v1.4.245.

## Implementation

- `Dockerfile` — `FROM docker.io/ubuntu:24.04`. Extras: `curl`, `git`, `libpulse0`,
  Noto fonts, and `gh` from GitHub's APT repo (same block as `apps/opencode`).
  `ARG ORCA_RELEASE=latest` + `ARG CACHE_BUST`. `latest` is resolved to a tag
  through the `https://github.com/stablyai/orca/releases/latest` redirect
  (`curl -w '%{url_effective}'`, no API call), because the asset name carries
  the bare version: `releases/download/vX.Y.Z/orca-ide_X.Y.Z_<amd64|arm64>.deb`.
  A tag not starting `v<digit>` is refused, so a mobile tag fails early with a
  clear message instead of a 404.
- The `.deb` installs the app to `/opt/Orca/` (Electron binary `/opt/Orca/orca-ide`)
  and `/usr/share/applications/orca-ide.desktop` (`Exec=/opt/Orca/orca-ide %U`,
  `Icon=orca-ide`, `StartupWMClass=orca`). Its postinst symlinks
  `/usr/bin/orca-ide` → `/opt/Orca/resources/bin/orca-ide`, a bash shim that runs
  the bundled CLI with `ELECTRON_RUN_AS_NODE=1`. So the two `orca-ide`s differ:
  `/usr/bin/orca-ide` is the CLI, `/opt/Orca/orca-ide` the GUI.
- `exports` — `app:orca-ide:Orca` (package's own entry; content and basename
  both match `orca-ide`, so it lands at `orca-box-orca-ide.desktop`) and
  `bin:orca-ide` (the CLI). No `orca` command on the host: that would shadow
  GNOME's Orca screen reader.
- The Dockerfile rewrites the entry's `MimeType=` to just `x-scheme-handler/orca;`,
  dropping `text/markdown`, `text/csv`, `text/tab-separated-values`.
- `wizard/00-release.buildarg` — `releases|stablyai/orca` plus
  `tag-match|^v[0-9]+\.[0-9]+\.[0-9]+$`. `tag-match|` was added to the wizard
  format for this app (`tui/releases.go` `fetchMatchingReleases`,
  `lib/wizard.sh` `_wizard_buildarg_values`): it fetches 100 releases and keeps
  the newest 10 that match.
- `icon.png` — the package's `hicolor/256x256/apps/orca-ide.png`.
- `category` = `Development`, with the other agent tools.

## Pitfalls and notes

- **The repo's release feed is two products.** `mobile-android-v0.0.N` Android
  pre-releases are interleaved with desktop `v1.4.N` releases, so a plain
  `releases|` page showed Android builds the Dockerfile can't install. Also,
  some `v*` git tags (e.g. v1.4.236, v1.4.234) have no published release, and
  there are `-rc.N` tags, so a `git ls-remote` items-cmd (codex's approach)
  would have offered uninstallable versions. Hence `releases|` + `tag-match|`.
  `/releases/latest` skips pre-releases, so it always resolves to a desktop tag.
- **In-app updater.** `resources/package-type` is `deb`, and for that Orca builds
  a `sudo apt install ./orca-ide_X.Y.Z_amd64.deb` command from the downloaded update
  (`ste()` in `out/main/index.js`) rather than replacing files. Inside the box
  that would upgrade only until the next `tools setup`. Left alone and
  documented. Making `package-type` unusable would disable it, but also makes
  the app report "updater-unavailable".
- **Profile is `~/.config/orca/`** (lowercase), not `~/.config/Orca/`.
- First launch, Linux Mint 22.3 X11, v1.4.244: window `orca.orca` "Orca",
  renders the onboarding flow with no extra GPU flags or `create_flags`.
  The log has the usual `system_bus_socket` D-Bus errors (no system bus in a
  box) and `login1.Manager.Inhibit` failing; both harmless. Onboarding flagged
  `gh` missing, which is why it was added.
- `chrome-sandbox` is shipped `0755` and the postinst `chmod 4755`s it; it still
  works without SUID under rootless Podman (user namespaces), as for chatgpt.
- **distrobox-init's first-start packages are preinstalled** through the shared
  `lib/distrobox-deps` step, so it builds only through `tools`.
- Testing note: `pkill -f /opt/Orca/orca-ide` inside a compound shell command
  matches that shell's own command line and kills it; use `pkill -f '^/opt/Orca/orca-ide'`.
- **A stale dashboard binary ignores `tag-match|`.** `tools` builds
  `tui/tools-tui` only when it is missing, so in a working tree whose binary
  predates `tag-match|` the picker silently shows the Android pre-releases too
  (unknown page lines are skipped). Run `tools build-tui` after pulling Go
  changes. Release installs ship a binary CI built from the same tree.
