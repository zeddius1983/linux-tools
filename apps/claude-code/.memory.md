## claude-code

Packages the Claude Code CLI (Anthropic's AI coding assistant) into a Distrobox container and exports it to the host as both a binary (`claude`) and a terminal desktop shortcut.

## Implementation

- Base image: `ubuntu:24.04`
- Claude Code installed via the **official native-binary install script** (`curl -fsSL https://claude.ai/install.sh | bash`)
  - Run with `HOME=/opt/claude-install` so the installer's outputs land in a build-time directory
  - The script drops a symlink at `$HOME/.local/bin/claude` pointing to `$HOME/.local/share/claude/versions/<X.Y.Z>` (the real ~240 MB native binary)
  - We `cp -L` the dereferenced binary to `/usr/bin/claude` (a system path Distrobox's home-overlay does not hide) and delete `/opt/claude-install`
- GitHub CLI (`gh`) installed via the official GitHub APT repo
- Node.js 22 LTS installed via the NodeSource APT repo — bundled **only** to provide `npx` for launching npx-based MCP servers (e.g. context7); Claude Code itself does not need it
- Exports: `bin:claude` (host PATH) and `desktop:claude:Claude Code` (terminal shortcut)
- **Optional status line** (`wizard/00-statusline.packages` + `claude-code-install`): a Powerline/p10k-style status line, shipped opt-in via the setup wizard.
  - Reuses the existing `.packages` wizard type (like `dev-toolbox`) — **no `lib/` changes**. The wizard runs `claude-code-install --tools "statusline"` inside the box; because `$HOME` is shared, the installer writes to the host's `~/.claude/`.
  - `statusline.sh` is bundled into the image at `/usr/share/claude-code/statusline.sh` (a system path — the home overlay hides anything baked under `$HOME`). The installer copies it to `~/.claude/statusline.sh` and merges `.statusLine` into `~/.claude/settings.json` with `jq`.
  - Toggle-off (untick / `--tools ""`) removes the script and drops `.statusLine`, but only when it still points at our command, so a user's own status line is left alone.
  - Backups: an existing differing `statusline.sh` → `statusline.sh.bak-<ts>`; if `settings.json` already has a *different* `.statusLine`, the whole file → `settings.json.bak-<ts>` before we overwrite.
  - **OS icon is detected from the *host*, not the container.** The script runs inside the ubuntu box, so a naive `/etc/os-release` read would always show ubuntu. Distrobox bind-mounts the host root at `/run/host`, so `detect_os_icon()` reads `/run/host/etc/os-release` first (falling back to `/etc/os-release` when run bare-metal), maps `ID` (then `ID_LIKE`) to the matching powerlevel10k OS glyph, and falls back to a generic Tux (``). Arch-family distros with no own glyph (cachyos, endeavouros, artix…) resolve via `ID_LIKE=arch` → arch glyph ``.

## Pitfalls and notes

- **Why the install script and not APT?** The APT repo (`https://downloads.claude.ai/claude-code/apt/stable`) lags the install script by many patch versions (observed 2.1.153 on APT vs 2.1.178 from the script on the same day). The install script tracks `latest` from the release manifest.
- **Why override `$HOME` during the install?** The installer writes the launcher to `$HOME/.local/bin/claude`. Without override, image-build `$HOME=/root` puts it in `/root/.local/bin/`, which Distrobox's home-overlay hides at runtime → `cannot find 'claude' inside container`. Build-time `HOME=/opt/claude-install` keeps the install path off of any home path, then we copy the actual binary to `/usr/bin/`.
- **Why `cp -L`, not `mv`?** The installer's `$HOME/.local/bin/claude` is a symlink to `$HOME/.local/share/claude/versions/<X.Y.Z>`. A plain `mv` of the symlink would dangle once we remove `/opt/claude-install`. `cp -L` dereferences the symlink and produces a standalone binary that runs without the original layout (verified by deleting `/opt/claude-install` and running `/usr/bin/claude --version`).
- **Claude Code itself needs no `nodejs`/`npm`.** It ships as a single self-contained native binary, not an npm package. Node.js 22 LTS is nonetheless installed via NodeSource so that `npx` exists — npx-based MCP servers (context7, etc.) are spawned by `claude` at runtime via `npx -y <pkg>` and need a real Node.js in the container. Ubuntu's own `nodejs` package lags several majors, hence NodeSource. Verify after build with `distrobox enter claude-code-box -- npx --version`.
- **No self-update at runtime.** Container `/usr/bin/claude` is read-only to the user. The container's `claude install latest` (if invoked) would write to `$HOME/.local/...` on the host, which would *not* be picked up by the host-exported `bin:claude` wrapper (it always invokes the container's `/usr/bin/claude`). To upgrade, rebuild the image: `tools setup claude-code`.
- **The install script also writes `.claude.json` and `.claude/backups/` under `$HOME`.** These end up in `/opt/claude-install` and are discarded with the cleanup; user config at runtime lives on the host's `~/.claude/` as expected.
- **Status line wizard only runs interactively.** `tui_run_wizards`/`tui_apply_wizards` fire only when stdin is a TTY and `whiptail` exists (see `tools.sh` `setup`). A piped/non-interactive `tools setup claude-code` builds the image (statusline bundled at `/usr/share/claude-code/`) but does **not** touch `~/.claude/` — enable it later with `distrobox enter claude-code-box -- claude-code-install --tools statusline`.
- **settings.json merge is defensive.** `claude-code-install` refuses to write if `settings.json` exists but isn't valid JSON (never clobbers a hand-edited config), and it starts from `{}` when the file is missing/empty. `jq` is already in the image for this.
- **`.statusLine.command` is stored with a literal `$HOME`** (`bash $HOME/.claude/statusline.sh`) — Claude Code expands it at render time. The installer's removal/backup checks match on that exact string, so keep `STATUSLINE_CMD` in the script and the value written to settings identical.
