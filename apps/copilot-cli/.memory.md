## copilot-cli

GitHub's Copilot CLI agent (`copilot`), installed with GitHub's own installer
(`https://gh.io/copilot-install`, `PREFIX=/usr` so the binary lands in `/usr/bin`
where `command -pv` finds it). Exported as `bin:copilot` plus a terminal
`desktop:` entry.

## Implementation

- **Base image**: `docker.io/ubuntu:24.04`.
- **Dependencies**: `curl`, `ca-certificates`, `tar`, `libsecret-1-0` (keyring
  for the login token), `git`, and `gh` from GitHub's APT repo.
- **Exports**: `bin:copilot`, `desktop:copilot:GitHub Copilot CLI`.

## Pitfalls and notes

- **Maintained again** (Oct 2026): it was marked unmaintained for a while (an
  `unmaintained` marker file greyed it out in the dashboard and flagged it in
  `tools list`); the marker was removed to return it to the normal app list.
- The installer runs at image-build time, so a rebuild (`tools setup`) is the
  update path.
- Config/login live in `~/.copilot/` on the shared `$HOME`.
- **`FROM` is fully qualified** (`docker.io/ubuntu:24.04`, Oct 2026): it was grandfathered in `LEGACY_UNQUALIFIED_FROM`, which is now empty. Same image, but it no longer depends on the host having an unqualified-search registry configured.
- **distrobox-init's first-start packages are preinstalled** (2026-10-27) through the shared
  `lib/distrobox-deps` step near the top of the Dockerfile, so a fresh box's
  `Installing basic packages...` is a no-op instead of a ~250-package download (see
  "Distrobox first-start packages" in `CLAUDE.md`). It builds only through `tools`, which
  passes the `distrobox-deps` build context; a bare `podman build` fails at that `COPY`.
