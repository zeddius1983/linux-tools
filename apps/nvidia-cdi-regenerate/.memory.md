## nvidia-cdi-regenerate

Host-only app (no container). Installs a boot-time systemd oneshot that runs
`nvidia-ctk cdi generate --disable-hook disable-device-node-modification --output
/etc/cdi/nvidia.yaml`, so the CDI spec always matches the currently-installed GPUs.
Consolidates one of the five loose `~/` NVIDIA host artifacts into a versioned app.

## Implementation

- **Container-less host-only pattern.** Ships `host-only` + `install.sh` and **no
  Dockerfile**. `tools setup` detects this (`is_hostonly_installer` in
  `lib/helpers.sh`) and runs `install.sh` directly on the host — no image, no box.
  `tools rm` runs `install.sh uninstall`. This container-less path was added to
  `cmd_setup`/`cmd_rm` (`lib/commands.sh`) as part of this app set.
- **`install.sh`**: `sudo install -m644` the unit → `/etc/systemd/system`,
  `daemon-reload`, `enable --now`. Warns (doesn't fail) if `nvidia-ctk` is missing,
  since the unit's `ConditionPathExists=/usr/bin/nvidia-ctk` self-skips at boot.
- **Cross-distro:** the only dependency is nvidia-container-toolkit (`nvidia-ctk`,
  always at `/usr/bin` on Debian/Fedora/Arch) + systemd (universal). No per-distro
  branching needed beyond the missing-toolkit hint.
- **The unit** itself is unchanged from the version hand-installed on the CachyOS
  host earlier: `Type=oneshot`, `RemainAfterExit=yes`, `ExecStartPre=-nvidia-smi -L`
  (populate `/dev/nvidia*` before enumerating), soft `Wants=nvidia-persistenced`.

## Pitfalls and notes

- **Why boot-time, not one-shot:** the spec pins GPUs by UUID + device minors, so it
  goes stale whenever installed GPUs change (add/remove/move a card, PCIe-switch
  re-enumeration). This host churned 2×3090 → 3090+3080 → 2×3090+3080; each change
  broke `--device nvidia.com/gpu=all` until the spec was regenerated.
- **No box recreation needed** when the spec changes — Podman 6.0.1 re-reads
  `/etc/cdi/nvidia.yaml` on every container `start`. Regenerating the spec is
  sufficient; that's the whole point of doing it at boot.
- **The `disable-device-node-modification` hook** fails under distrobox (can't mount
  its `/proc/driver/nvidia/params`), surfacing as `nvidia-cdi-hook (exit code: 1)` on
  box start — hence `--disable-hook`. See [[cdi-disable-device-node-modification-hook]]
  and `apps/nvtop/.memory.md` for the full two-trigger write-up.
- **ExecStart absolute path:** systemd requires an absolute `ExecStart`, so the unit
  hardcodes `/usr/bin/nvidia-ctk`. That's the standard location on all three distro
  families; a host that installs it elsewhere would need the unit edited.
- Do NOT use `distrobox create --nvidia` on this host — it hangs in a driver-remount
  loop; CDI is the supported path (see [[distrobox-nvidia-use-cdi-not-nvidia-flag]]).
