## lact

[LACT](https://github.com/ilya-zlobintsev/LACT) — Linux GPU Control Application:
GTK4 GUI plus a system daemon for AMD/NVIDIA/Intel GPU power caps, fan curves,
clock and voltage offsets, power states and per-process settings profiles.

Packaged for the release picker and the one-command install/uninstall, not for
containerisation — see below.

## Implementation

**Host-only, with `install.sh` — not a container.** This is the important
decision and it is forced, not stylistic. `lactd` runs as root and writes GPU
control files under `/sys/class/drm/*/device/`; a rootless Podman container
cannot do that with any amount of `--privileged`, the same wall `corefreq` hits
with `insmod`. Upstream's own container image
([docs/DOCKER.md](https://github.com/ilya-zlobintsev/LACT/blob/master/docs/DOCKER.md))
is daemon+CLI only with **no GUI**, and documents rootful Docker with
`--privileged -v /dev/dri:/dev/dri`. So the app joins `nvidia-cdi-service` and
`nvidia-acs-service` in the `host-only` + `install.sh` category
(`is_hostonly_installer` in `lib/helpers.sh` requires the marker **and**
`install.sh` **and** no Dockerfile).

**Core change this app required: `.buildarg` answers now reach host-only
installers.** A `.buildarg` page's value is consumed by `cmd_build` as
`--build-arg`. A host-only app never builds an image, so a version picker on one
would have been collected by the wizard and then silently thrown away. `cmd_setup`'s
host-only branch now converts `wizard_build_args` output into environment
assignments and runs `install.sh` under `env`. `install.sh` reads
`LACT_VERSION`, defaulting to `latest`. This generalises: any future host-only
app gets wizard answers the same way.

**Release picker uses `items-cmd` + `notes-repo`, not `releases|`.** Two reasons,
both discovered from the live API:

1. The API returns the rolling `test-build` prerelease **first**, so a plain
   `releases|ilya-zlobintsev/LACT` page would default to a dev build — a poor
   default for something that writes voltage curves. The `items-cmd` filters to
   `v[0-9]*` tags in API order, so the default is the newest *stable* release.
2. `test-build` is still worth offering (upstream documents it as the way to get
   unreleased fixes), so it is appended inside the `items-cmd` itself.

`notes-repo|ilya-zlobintsev/LACT` then attaches each tag's changelog and date, so
the picker shows release notes exactly as a `releases|` page would.

**Asset resolution is done from the release's asset list, never by building a
filename.** Upstream ships one package per distro release, and the installer
walks a priority list of name fragments from `/etc/os-release`.

## Pitfalls and notes

- **`extra|` does nothing on an `items-cmd` page.** It is only read on the
  `releases|` path (`buildArgItems` in `tui/wizardui.go` appends `p.Extra` inside
  the `ReleasesRepo` branch and returns before the items-cmd path). A page that
  writes `extra|test-build` next to an `items-cmd` gets no error and no extra
  entry — the line is silently ignored. That cost a debugging round here; the
  fix is the established idiom of folding the literal into the command itself,
  the way `openclaw` and `codex-cli` prepend `latest`.

- **Every release ships a `lact-headless-*` twin for each distro target.** A
  naive `grep ubuntu-2404.deb` matches both, and picking the headless build
  installs a daemon with no GUI — a failure that looks like "the GUI package is
  broken" rather than "wrong package". The matcher excludes names beginning
  `lact-headless-`.

- **`test-build`'s assets are not named after its tag.** It is rebuilt from the
  latest commit continuously and carries whatever version it was built from
  (`lact-0.10.1-*` at the time of writing), while GitHub shows it with a 2023
  date. Any code that constructs a download URL from the tag breaks on it. This
  is why the installer reads `browser_download_url` from the release JSON —
  verified against `latest`, a pinned `v0.9.1`, and `test-build`, all three of
  which resolve correctly.

- **Ubuntu derivatives need `UBUNTU_CODENAME`, not `VERSION_ID`.** Mint 22.3
  reports `ID=linuxmint`, `VERSION_ID=22.3`, `UBUNTU_CODENAME=noble`. Its own
  version number means nothing to LACT's asset names; the codename is what maps
  to `ubuntu-2404.deb`. The same applies to Pop!_OS and elementary.

- **Do not `source install.sh` to test its functions.** The dispatcher at the
  bottom runs on source, which during development here started a real install
  (it got as far as `sudo apt-get install` before failing for want of a TTY).
  Extract the function with `sed -n '/^name()/,/^}/p'` and source that instead.

- **The sudo half of the install has never been executed.** Asset resolution,
  distro detection and the wizard are all verified, but package installation and
  `systemctl enable --now lactd` were not — the development session had no
  passwordless sudo. The README's badges are grey for that reason; flip Ubuntu
  and Mint after a real run.

- **AMD overclocking needs `amdgpu.ppfeaturemask=0xffffffff`** on the kernel
  command line, or the controls are present but inert. LACT's GUI can write the
  bootloader change itself. Worth knowing before concluding the app is broken on
  an AMD card.
