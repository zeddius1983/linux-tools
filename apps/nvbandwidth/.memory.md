## nvbandwidth

NVIDIA's GPU memory-bandwidth benchmark (host↔device and device↔device /
NVLink). CLI-only, exported as `bin:nvbandwidth`. NVIDIA-only, so unlike
`lmstudio` there is no AMD/NVIDIA runtime picker — it always uses CDI passthrough.

## Implementation

- **Base image:** `docker.io/nvidia/cuda:12.6.3-devel-ubuntu24.04`. The `-devel`
  image supplies `nvcc` + the CUDA toolkit to compile, plus the runtime libs the
  binary needs (libcudart etc.). Ubuntu 24.04 ships cmake 3.28 (>= the 3.20
  minimum).
- **Build at image-build time** (not runtime like corefreq). nvbandwidth has no
  host-kernel ABI dependency — the only build-time variable is the target GPU
  arch, which we pin explicitly, so a GPU is not needed to build.
- **Stubs on `LIBRARY_PATH`:** nvbandwidth links `-lcuda` (libcuda.so.1, the
  driver) and `-lnvidia-ml` (NVML). Neither exists at build time — the real
  driver is injected only at runtime via CDI. The CUDA toolkit ships link stubs
  for both in `/usr/local/cuda/lib64/stubs`; `ENV LIBRARY_PATH=` that dir so the
  linker resolves them. Stub soname is `libcuda.so.1`, so at runtime the loader
  picks up the CDI-injected driver lib — no relink needed.
- **Pinned arch list:** `-DCMAKE_CUDA_ARCHITECTURES="75;80;86;89;90"`. The
  CMakeLists auto-detects arch from the GPU (then from nvcc) when the user does
  not set it; with no GPU at build time we set it explicitly. 86 = the box's
  RTX 3080.
- **Binary → `/usr/bin/nvbandwidth`** (via `install`), because `command -pv`
  (used by the `bin:` export) ignores `/usr/local/bin`.
- **CDI passthrough:** `create_flags` = `--device nvidia.com/gpu=all` only. Pure
  CUDA compute — no `/dev/dri`, no render/video group, no `/dev/kfd` (that's AMD).

## Pitfalls and notes

- **Host CDI spec is a hard prerequisite.** `--device nvidia.com/gpu=all` needs
  `/etc/cdi/nvidia.yaml` on the host (`nvidia-ctk cdi generate`). Missing → podman
  `no such device nvidia.com/gpu=all` at create time. Documented in README.
  Regenerate after driver updates. Do NOT use `distrobox create --nvidia` — it
  hangs in a driver-remount loop on this CachyOS + rootless-podman host (see the
  lmstudio memory / [[distrobox-nvidia-use-cdi-not-nvidia-flag]]).
- **CMake FetchContent pulls argparse** (p-ranav/argparse v3.2) from GitHub at
  build time → the image build needs network + `ca-certificates`. It is not a
  system package; do not try to `apt install` it.
- **`git describe` in CMakeLists:** the source is a `--depth 1` clone with no
  tags, so `git describe --always --tags` falls back to the short hash for the
  embedded version string. Harmless. `git` must be installed for it to run.
- **Single-GPU boxes:** device↔device NVLink testcases report unsupported; the
  host↔device PCIe tests still run. NVLink numbers need ≥2 NVLink-linked GPUs.
- **README has a P2P / PCIe-switch cheat-sheet** (added for a PEX88096
  bifurcation-board question). Canonical P2P testcases are `device_to_device_*`
  (`_ce`/`_sm`; `_tma` is Hopper `sm_90`+ only). Two caveats documented there:
  GeForce (3090/4090) has PCIe P2P disabled in the stock driver (works only over
  NVLink bridge, or via the tinygrad open-kernel-modules P2P patch), and PCIe ACS
  redirects peer TLPs to the root complex, defeating switch-local P2P unless
  disabled. `nvidia-smi topo -m` (NV#/PIX/PXB/SYS) is the transport ground-truth.
- **README has an "Enabling PCIe P2P on consumer GPUs" section.** Stock driver
  disables GeForce PCIe P2P → `device_to_device_*` waived on a bridge-less box.
  Fix = patched open kernel module (**host** op; CDI passes it through, no image
  rebuild). Preferred fork: `aikitoria/open-gpu-kernel-modules` (version-named
  `master` branch tracks e.g. driver 610.43.03, explicitly supports 3090 via PCIe
  BAR1 when no NVLink; `main` is unpatched upstream — do NOT use). Hard req:
  IOMMU passthrough (`iommu=pt`). ACS-disable + resizable BAR for full bandwidth.
  pacman driver upgrades clobber the patch (must re-run install.sh). Section
  includes a real-world worked example (LocalLLaMA u/panchovix 7-GPU AM5 build):
  PEX88096 (96-lane PCIe4 switch, ~$400) gives ~52 GB/s bidirectional same-gen
  Ampere P2P (incl. 3090); P2P only helps same-generation pairs; NCCL won't P2P
  across switches without a faked NCCL_TOPO_FILE; IOMMU must be `iommu=pt`.
- **Verified end-to-end on hardware** (2×RTX 3090, PCIe Gen4 x8, CUDA 12.6
  runtime / driver 610.43.03, sm_86): builds clean via the stub-link path, both
  GPUs enumerate, host↔device ~13 GB/s (= Gen4 x8), local VRAM read ~850–894 GB/s
  (~93% of the 3090's ~936 GB/s spec). All `device_to_device_*` waived ("P2P not
  supported") — expected: no NVLink bridge + stock-driver GeForce PCIe-P2P
  disabled. TMA testcases waived (needs sm_90+). Confirms the arch pin and the
  P2P caveats in the README.
