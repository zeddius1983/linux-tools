## nvtop

`htop`-style multi-vendor GPU TUI (NVIDIA / AMD / Intel / …) with a per-process
GPU table. Complements the vendor-specific `amdgpu_top` and `nvbandwidth` apps by
showing every GPU in one view. TUI-only → exported as `bin:nvtop` +
`desktop:nvtop` (terminal-launched).

## Implementation

- **Base image:** `registry.fedoraproject.org/fedora:43`. Fedora ships an
  `nvtop` package built with all backends enabled, so a single `dnf install
  nvtop` gets NVIDIA + AMD + Intel support — no source build, no CUDA toolkit.
- **NVIDIA path = NVML dlopen + CDI.** nvtop does not link the NVIDIA driver; its
  NVIDIA backend `dlopen()`s `libnvidia-ml.so.1` at runtime. That lib is injected
  by CDI (`create_flags` = `--device nvidia.com/gpu=all`), the same passthrough
  nvbandwidth uses. So no CUDA/driver is needed at image-build time.
- **AMD/Intel path = default device passthrough.** Those backends read libdrm +
  `/sys/class/drm` / `/dev/dri`, which Distrobox exposes by default — this is why
  the sibling `amdgpu_top` app needs no `create_flags` at all. nvtop inherits the
  same access, so AMD/Intel monitoring works regardless of the NVIDIA flag.
- **Exports:** `bin:nvtop` (host PATH) + `desktop:nvtop:nvtop` (terminal window
  launcher). No `gui:` — it's a curses TUI, not a windowed app. No bundled icon
  (falls back to `utilities-terminal`).

## Pitfalls and notes

- **Host CDI spec is a hard prerequisite** for the `--device nvidia.com/gpu=all`
  flag: needs `/etc/cdi/nvidia.yaml` (`nvidia-ctk cdi generate`). Missing → podman
  `no such device nvidia.com/gpu=all` at create time. Regenerate after driver
  updates. Do NOT use `distrobox create --nvidia` on this CachyOS + rootless-podman
  host — it hangs in a driver-remount loop (see
  [[distrobox-nvidia-use-cdi-not-nvidia-flag]]).
- **AMD/Intel-only hosts:** the CDI flag would make `tools setup` fail on a
  machine with no NVIDIA driver. Documented workaround in the README: delete
  `create_flags` — AMD/Intel still work via default passthrough.
- **If NVIDIA GPUs don't show up** but nvtop otherwise runs, it's an NVML resolve
  problem: the CDI-injected `libnvidia-ml.so.1` must match the loaded host driver.
- **Verified end-to-end on hardware** (2026-07-23, CachyOS, 2×RTX 3090): image
  205 MB, nvtop 3.3.2, `libnvidia-ml.so.1` present via CDI, `/dev/nvidia0/1` +
  `/dev/dri/{card0,card1,renderD128,renderD129}` visible in the box, and a live
  frame enumerates "GeForce RTX 3090". Pattern mirrors amdgpu_top (default
  passthrough) + nvbandwidth (CDI).
- **Host `tools` not on PATH:** on this host `tools` is not symlinked in
  `~/.local/bin`, and there are two repo checkouts
  (`~/Developer/linux-tools` = canonical + `~/Developer/projects/linux-tools`).
  Drive setup with `distrobox-host-exec bash -lc './tools.sh setup nvtop'` from
  the working copy rather than the `tools` shim.
