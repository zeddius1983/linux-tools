## copilot-app

The GitHub Copilot app (https://github.com/features/copilot): GitHub's desktop app
for running, steering and landing agent work across repositories. It is a Tauri
app (WebKitGTK 4.1, not Electron), installed from the official `.deb` on
`github/app`'s latest release in an `ubuntu:24.04` box and exported to the host
menu. Added Oct 2026 at release v1.1.34.

## Implementation

- `Dockerfile` — `FROM docker.io/ubuntu:24.04`. Downloads
  `https://github.com/github/app/releases/latest/download/GitHub-Copilot-linux-${arch}.deb`
  (`arch` is `x64`/`arm64`, mapped from `dpkg --print-architecture`) and installs
  it with `apt-get install ./file` so apt resolves its `Depends:`
  (`libwebkit2gtk-4.1-0`, `libgtk-3-0`, `libayatana-appindicator3-1`).
  `ARG CACHE_BUST` (set fresh by `cmd_build`) is echoed in that `RUN`, so every
  `tools setup` fetches the current release. There is no APT repo and no
  in-place update path for the `.deb`.
- Extras: `curl`, `git` (the app requires Git), `libsecret-1-0`, `libasound2t64`,
  `libasound2-plugins` + `/etc/asound.conf` (see pitfalls), Noto fonts.
- The package installs `/usr/bin/github` (the app, ~570 MB binary),
  `/usr/bin/git-credential-copilot`, `/usr/lib/GitHub Copilot/` and
  `/usr/share/applications/GitHub Copilot.desktop` (`Exec=github %u`,
  `Icon=github`, `StartupWMClass=github`, scheme handlers for `github-app`, `ghapp`
  and `gh`, empty `Categories=`).
- `exports` — `app:copilot-app:GitHub Copilot` and `bin:copilot-app`. The
  Dockerfile renames the desktop file to `copilot-app.desktop`, sets
  `Exec=copilot-app %u`, drops `MimeType=` and fills `Categories=Development;`
  (see pitfalls). Upstream's binary name `github` is too generic for the host
  PATH, hence the `copilot-app` launcher.
- `copilot-app` (→ `/usr/bin/copilot-app`) — launcher. On every start it writes
  `~/.local/share/applications/copilot-app-box-url-handler.desktop` (hidden,
  `Exec=$HOME/.local/bin/copilot-app %u`, the three scheme MimeTypes) and sets it as
  the default in `~/.config/mimeapps.list` with the same awk edit as
  `apps/telegram/telegram-desktop`. A URL argument starts `/usr/bin/github`
  detached (`setsid -f`) and returns; otherwise it `exec`s it. The handler's
  `copilot-app-box-` prefix makes `cmd_rm` (and so every `tools setup`) remove it.
- `icon.png` — the package's `icons/128x128@2x.png` (256px).
- `category` = `Development`, next to `copilot-cli`.

## Pitfalls and notes

- **`app:` export name.** `distrobox-export --app NAME` greps `/usr/share/applications`
  for `Exec=.*NAME` or `Name=.*NAME` (content, case-sensitive, not filename), then
  writes `<box>-<original filename>`. `tools.sh` post-processes
  `<box>-<NAME>.desktop`, so the export name must match both the file's content and
  its basename. Upstream's file is `GitHub Copilot.desktop`, which would export as
  `copilot-app-box-GitHub Copilot.desktop` and skip the Name/Icon fixup; renaming it
  to `copilot-app.desktop` with `Exec=copilot-app %u` makes `app:copilot-app` land
  at `copilot-app-box-copilot-app.desktop`.
- **`libasound.so.2` is linked but not in the package's Depends.** Without
  `libasound2t64` the binary exits immediately with
  `error while loading shared libraries: libasound.so.2`. `ldd` over
  `/usr/bin/github` and every bundled `.so` showed it as the only missing library.
- **ALSA has no device in a box.** With only `libasound2t64`, the log fills with
  `Unknown PCM pulse/pipewire` / `unable to open slave`. `libasound2-plugins`
  plus `/etc/asound.conf` (`pcm.!default pulse`, `ctl.!default pulse`) route ALSA
  to the host's Pulse/PipeWire socket; the errors are gone after that. Sound
  playback itself was not listened to.
- **State is shared with `copilot-cli`.** The app writes `~/.copilot/`
  (`data.db`, `session-state/`, `chats/`, logs) and downloads a
  `copilot-sdk-runtime` into `~/.cache/github-copilot-sdk/`, run as
  `copilot-runtime --server --stdio --no-auto-update`. It also unpacks its own
  `git` and `gh` into `~/.cache/github-copilot-git-*` and
  `~/.cache/copilot-desktop-gh-*`. `~/.config/github-copilot/auth.db` existed on
  the test host before the app was installed; the app started already signed in,
  but which credential it used was not established.
- **Scheme handlers (PR #93 review).** The first version exported upstream's entry
  with its `MimeType=`, so the handler's Exec was `distrobox-enter …`, which
  exists only on the host: a link clicked in Chrome (`chrome-box`) runs xdg-open
  in that box and couldn't start the app. Fixed with the launcher above. Unlike
  Telegram, the app does not register handlers itself (nothing appeared in
  `~/.local/share/applications` or `mimeapps.list` after running it), so the
  private-`XDG_CURRENT_DESKTOP` trick isn't needed. Trade-off: the handler exists
  only after the first launch since the last `tools setup`.
- **Re-export duplicated the handler (fixed in `lib/commands.sh`).** `distrobox-export
  --app` also searches `$XDG_DATA_HOME/applications`, i.e. the shared
  `~/.local/share/applications`, and greps for `Exec=.*copilot-app` there too. A plain
  `tools export copilot-app` (no `cmd_rm` first, unlike `setup`) therefore matched
  the launcher's own `copilot-app-box-url-handler.desktop` and wrote a broken
  `copilot-app-box-copilot-app-box-url-handler.desktop`. `cmd_export` now runs
  `distrobox-export --app` with `XDG_DATA_HOME=/nonexistent`, so only the image's
  entries are searched; every `app:` app installs into `/usr/share/applications`,
  and chatgpt re-exported unchanged.
  Verified 2026-10-31: `xdg-mime query default` gives the handler on the host and
  in `chrome-box`; `distrobox enter chrome-box -- xdg-open ghapp://open` with the
  app stopped cold-starts it (`/usr/bin/github ghapp://open`) and returns; with it
  running, a second link is handed over (still one process, one window).
- **Plan requirement.** Upstream's README (v1.1.34) says any Copilot plan works,
  Free and Student included, and BYOK works with no plan. A search summary of
  the GitHub docs had claimed paid plans only; trust the upstream README.
- **`Locale not supported by C library`** warnings in the log come from the
  host's `LC_*=ru_RU.UTF-8`, which distrobox-init doesn't generate in the box
  (it only generates `LANG`). Harmless; affects every Ubuntu box.
- Verified 2026-10-31 on Linux Mint 22.3 (X11): starts in ~15s, window class
  `github.Github`, signed-in home screen renders (WebKitGTK, no extra GPU flags).
- **distrobox-init's first-start packages are preinstalled** through the shared
  `lib/distrobox-deps` step, so it builds only through `tools` (see "Distrobox
  first-start packages" in `CLAUDE.md`).
